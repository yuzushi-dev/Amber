## Release 1.5.0

**Period:** 2026-06-03 to 2026-06-04
**Commits:** 60
**Deployed to production:** 2026-06-04

---

## Overview

A hardening and correctness release driven by a full internal audit of every
pipeline subsystem (documented internally). The audit surfaced ~80
issues; this release fixes them across security (Postgres RLS), retrieval and
caching correctness, ingestion state handling, graph/community integrity,
provider resilience, memory persistence, multi-tenancy, and worker
orchestration — plus removal of dead code and misleading stubs. Two RLS
migrations are included. No data-loss risk: migrations are policy-only and
reversible; destructive operations are scoped or act only on derived,
re-generatable data.

---

## Security

| Area | Fix |
| ---- | --- |
| **RLS GUC bleed** | `app.is_super_admin` was set session-scoped only on super-admin requests and never reset, so a pooled connection that served a super-admin let a later non-super request bypass RLS. Now set unconditionally (`true`/`false`) alongside `app.current_tenant` on every session path (request deps, unit of work, worker session). |
| **RLS on `user_facts` / `usage_logs`** | These tenant tables had `tenant_id` but no row-level security. Added `ENABLE`/`FORCE RLS` + tenant-isolation policies (migration `20260603_1200`). `UsageTracker` write path now sets the GUC so inserts keep working under RLS. |
| **Group-based chunk reads** | Added `chunks_group_read` RLS policy mirroring `documents_group_read` so chunk reads honour group access under `groups_enforced` (migration `20260603_1300`). |
| **Agent graph tool** | `query_graph` ran raw LLM-authored Cypher with no tenant predicate. Now a `create_graph_tool(tenant_id)` factory enforces read-only Cypher and binds the caller's `tenant_id` from trusted context (rejects queries lacking `$tenant_id`). |
| **Group management authorization** | Groups endpoints accept any admin — super-admin OR global `admin` scope OR per-tenant admin role (`verify_group_admin`) — consistent and without locking out existing admins. |
| **Chat-history redaction** | Now opt-in via `CHAT_REDACT_WITHOUT_FEEDBACK` (default **false** → admins see full content as before). When enabled, no-feedback conversations are redacted. |

## Retrieval & Cache

- **Result-cache key completeness**: the key excluded `search_mode`, `top_k`, embedding model, and active collection — different requests collided and served stale/wrong results. Key now includes all of these and is namespaced `result:{tenant_id}:{hash}` so per-tenant invalidation works.
- **Cache invalidation wired**: `invalidate_tenant` had no callers; the cache served stale answers up to its TTL after content/config changes. Now invalidated (best-effort, non-fatal) on document ingestion completion, document delete, and tenant config update/reset.
- **STRUCTURED mode**: the router could emit `SearchMode.STRUCTURED` but it silently fell back to vector search. Now dispatched through the structured executor (with a vector fallback + warning if unavailable); `QUERY_MODE_PROMPT` documents the mode.
- **Embedding ↔ Milvus dimension guard**: a query/insert whose embedding dimension differed from the target collection surfaced as an opaque Milvus 500. Added an explicit parity check (clear error) before search/upsert and `embedding_supports_dimensions` enforcement on reduced-dimension requests.
- **Dead RRF/hybrid path removed**: `_execute_hybrid_search` + fusion/weights were never dispatched by `retrieve()`. Removed. DRIFT no longer computes a synthesis answer that was discarded (wasted LLM call). Inert `traversal_depth` option removed.

## Ingestion & Document State

- **Silent partial-ingest fixed**: graph-sync (stage 7) and enrichment (stage 8) failures were swallowed, so a document reached `READY` with a missing/partial graph and no signal. They now propagate to `FAILED` with a persisted error (recoverable).
- **Stale-store cleanup on re-ingest**: re-processing a document now deletes its existing Milvus vectors and Neo4j chunk nodes (scoped to `document_id` + `tenant_id`) before re-writing, instead of leaving orphans.
- **Transition validation wired**: `TransitionManager.validate_transition` is now enforced at the ingestion status transitions.
- **Extractor routing**: `FallbackManager` now passes `file_extension` to the registry (extension-only routing works); extractor `extract()` parameter unified to `mime_type`.
- **Quality gate default OFF**: `mark_low_quality_as_needs_review` defaults to `false` (no `NEEDS_REVIEW` release workflow exists yet); enable via env once one does.

## Graph & Communities

- **Reconciliation**: `GET /v1/admin/maintenance/reconciliation` was a hard-coded "healthy" stub. Now performs a real per-tenant count comparison across Postgres/Neo4j/Milvus and reports `healthy`/`drift_detected` (detection only).
- **Stale-community prune**: `POST /v1/admin/maintenance/prune/stale-communities` was a stub returning 0. Now `DETACH DELETE`s `:Community` nodes that are `is_stale` AND older than `max_age_days` (default 30), tenant-scoped, derived data only.
- **Community lifecycle `e.id` no-op**: `mark_stale_by_entities` / `cleanup_orphans` matched a non-existent `Entity.id`; fixed to key on `name` + `tenant_id`.
- **Community embedding model**: community summaries were embedded with the system-default model while GLOBAL search queried with the tenant-resolved model — silently breaking GLOBAL similarity on tenants with an embedding override. The write path now resolves the embedding model from `tenant_config`.
- **Leiden parameters** (`resolution`/`max_levels`/`seed`) exposed as settings (defaults unchanged).
- **Dedup honesty**: `hard_merge` now raises `NotImplementedError` instead of logging success; the `LIMIT 1000` candidate cap logs a warning; `graph_traversal_guard.filter_path_query` enforces a document predicate instead of being a no-op.

## Generation, Providers & Agent

- **Failover `chat()`**: `FailoverLLMProvider` / `LoadBalancedLLMProvider` overrode only `generate()`/`generate_stream()`, so `chat()` raised `NotImplementedError` — breaking the agent under `LLM_FALLBACK_ENABLED`. Both wrappers now delegate `chat()` with the same failover logic; `openai.chat` handles the injected `model`/`work_class` kwargs.
- **Failover robustness**: generic provider errors now advance to the next provider instead of aborting the chain; non-`ProviderError` exceptions are caught.
- **Agent system prompt** trimmed to advertise only wired tools; `tools_used` now logs the tools actually invoked.
- Dead `FailbackManager` removed. The latency monitor formerly named `CircuitBreaker` renamed to `LatencyMonitor` to end the name collision with the provider circuit breaker.

---

## Memory & Multi-tenancy

- **Multi-turn history on non-stream queries**: `POST /v1/query` plain-INSERTed a summary with no history and PK-collided on turn ≥2, so only turn 1 persisted. Now upserts and appends to `metadata_["history"]` (and sets the tenant GUC so the write passes RLS).
- **Retention endpoints**: `list_facts`/`list_summaries` opened a raw session without the tenant GUC (returning empty under RLS) and hardcoded `tenant_id="default"`. Now use the configured DI session and derive tenant from admin context.
- **Linkless API key**: the legacy "no `api_key_tenants` → default tenant" fallback is now gated behind `ALLOW_LINKLESS_KEY_DEFAULT_TENANT` (default true) and logs a warning.

---

## Workers & Recovery

- **Cooperative cancellation**: long/destructive tasks now check for revocation at safe points (notably before the destructive full-Leiden wipe), so cancellation stops them cleanly instead of relying on SIGKILL + re-queue.
- **Periodic recovery sweep**: stuck-document recovery, previously boot-only, now also runs on a 10-minute beat schedule — with an age threshold (`min_age_minutes=30`) so it never resets documents that are legitimately mid-processing (boot path keeps `0`).
- **Task time limits**: added `task_soft_time_limit=3600` / `task_time_limit=7200` so a wedged task can't hold a worker slot forever.
- **Jobs API honesty**: `GET /v1/admin/jobs/{id}` distinguishes TTL-expired from unknown; dead `ingestion`/`extraction` task routes removed.
- **Embedding migration**: `migrate_tenant` now targets the actual active collection via `resolve_active_vector_collection` (instead of a hardcoded `amber_<id>`) and persists progress/cancel state in Redis (survives restart, multi-replica safe). Documented as still destructive in-place; blue/green deferred.
- **Config cache**: `TuningService` tenant-config cache now has a 30s TTL plus a best-effort Redis version check, so config changes (e.g. active collection flip) converge across API replicas instead of going stale until restart.

## Behaviour & Default Changes

- Chat-history redaction is **off by default** (opt-in via `CHAT_REDACT_WITHOUT_FEEDBACK`).
- Ingestion quality gate is **off by default** (`mark_low_quality_as_needs_review=false`).
- Documents that fail graph-sync/enrichment now reach `FAILED` (retryable) instead of `READY`-without-graph.
- After deploy, the result cache cold-starts (new key scheme) — a transient one-time latency/cost blip while it re-warms.
- A leftover `print("DEBUG: …")` in LLM-step resolution was removed.
