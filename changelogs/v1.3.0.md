**Period:** 2026-03-31 to 2026-04-24

## Overview

This release delivers query-complexity-aware model routing, a complete feedback system overhaul, per-user conversation history in the client view, inline document viewing, and a full super-admin multi-tenant visibility layer. It also ships cross-tenant usage metrics for super admins, a production-ready frontend build pipeline, and a rewritten backup script for the Garage stack.

---

## Query Complexity Routing (ZTD-1819)

- Added `QueryComplexityRouter`, a deterministic zero-LLM scorer that maps each query plus its RAG context to one of four tiers: `simple`, `standard`, `complex`, or `reasoning`.
- Scoring uses 9 dimensions: word count, comparison signals, synthesis signals, all-docs scope, risk/compliance language, multi-task structure, distinct document count, chunk count, and context token count.
- Each tier routes to a different Ollama model configured per tenant; the router is opt-in via `complexity_routing.enabled` in tenant config and has no effect on tenants that do not enable it.
- An Ollama thinking mode (`extra_body: {think: true}`) is supported in code at the `reasoning` tier; it requires a dedicated `max_tokens` budget and is currently disabled in production.
- A `complexity_tier` SSE event is emitted in streaming responses for observability.
- 18 unit tests added covering all tiers, English/Italian parity, RAG context signals, and multi-task detection.

## Feedback System (ZTD-1818, 1823, 1824)

- Admin feedback view is now tenant-scoped: tenant admins see only their own tenant's feedback; super admins see all tenants.
- Users can re-submit feedback and flip the polarity (thumbs-up to thumbs-down and vice versa) on an already-answered question without creating duplicate records.
- ThumbsUp/ThumbsDown icon in the feedback list now reflects the actual polarity of each record instead of a fixed icon.

## User-Facing Conversation History (ZTD-1822)

- Added a conversation history panel to the client chat view (`/amber/chat`), matching the sidebar experience already available to admins.
- History is scoped to the authenticated user and tenant; cross-user or cross-tenant conversations are not visible.

## Inline Document Viewer (ZTD-1821)

- Added a "View Document" button to document rows in the client document list.
- Opens an inline file viewer without leaving the page, using the existing `DocumentViewer` component.

## Memory Context Fix (ZTD-1820)

- Cross-session conversation summaries are no longer injected into the memory context window for new queries.
- Only summaries belonging to the current session are included, preventing stale context from unrelated past sessions from influencing answers.

## Admin Chat History and UX

- Unified admin and client chat sidebar: both views now share the same component and data source with role-appropriate filtering.
- Super admins can browse chat history across all tenants from the admin view.
- Privacy redaction removed from admin chat history; full query and answer text is now visible to admins with appropriate access.
- Token metrics (input tokens, output tokens, cost) added to the chat detail view.
- Interactive source viewer added to admin chat detail: admins can click through cited chunks to read the original source text without leaving the dialog.
- `Feedback.conversation_id` corrected to `request_id` in `chat_history.py`; affected records were displaying mislinked context.

## Super-Admin Multi-Tenant Visibility

- Super admins now see documents and folders across all tenants in the document listing endpoints; previously listing was limited to the tenant context of the API key.
- Super-admin folder listing returns a unified logical view that deduplicates shared and per-tenant folders.
- Query scope resolution extended to include all tenant namespaces for super-admin requests, enabling cross-tenant search and retrieval.
- Shared document `folder_ids` are normalized for regular-tenant responses so that tenant-local folder references are not leaked.

## Cross-Tenant Usage Metrics (PR #8)

- New super-admin endpoint and admin UI panel for cross-tenant token usage metrics.
- Shows input/output token counts, cost estimates, and query counts per tenant, aggregated over configurable time windows.

## Infrastructure

- **Production frontend build**: `Dockerfile.prod` added with a multi-stage Nginx build. A `docker-compose.override.prod.yml` enables the production frontend container in the standard Compose stack.
- **Backup script rewrite**: `scripts/backup.sh` rewritten for the Garage object-storage stack. Supports `--dry-run` for safe pre-flight checks; covers PostgreSQL, Neo4j, Milvus, Redis, and Garage buckets.
- **Structured logging**: API response logging now emits structured JSON with request ID, method, path, status code, and latency, enabling log aggregation and alerting.
- **Debug scripts relocated**: ad-hoc `src/test_*.py` scripts moved to `scripts/debug/` to keep the source tree clean.

## Bug Fixes

| Fix | Detail |
|-----|--------|
| SQLAlchemy mapper error in worker | `DocumentShare` mapper was not registered at worker startup; resolved by importing the model in the worker entrypoint |
| Missing `app.current_tenant` GUC in worker tasks | Worker sessions now always issue `SET app.current_tenant` before executing tenant-scoped queries |
| Chrome/Windows `scrollIntoView` crash in CitationExplorer | Replaced synchronous `scrollIntoView` call with a guarded async alternative to avoid cross-origin frame errors on Chrome/Windows |
| CORS wildcard refused in production | `allow_origins=["*"]` is now rejected at startup in non-debug mode with a clear error message; `SECRET_KEY_OLD` left set in production triggers a warning |
| `app.current_tenant` GUC not set on every request | Auth middleware now sets the GUC unconditionally on every authenticated request, not only when tenant provisioning runs |
| Neo4j/Milvus shutdown `aclose()` error | Platform shutdown now calls `.close()` instead of `.aclose()` on Neo4j and Milvus clients, matching their actual interface |
| Document detail page broken for client users | `/amber/documents/:id` route was missing from the client router; added with the correct auth guard |
| `ChatDetailDialog` syntax error and missing state | Frontend syntax error in the dialog component corrected; missing `sourcesById` state restored |
