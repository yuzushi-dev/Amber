## Overview

This release ships the MinIO storage migration (replacing Garage), Ollama Cloud as a first-class LLM provider with multi-key failover, hybrid sparse-dense search, eight backend improvements from the PR backlog (result cache, injection guard, MIME validation, DRIFT timeout, search mode metrics, Swagger gate, Milvus decoupling), and a comprehensive frontend performance audit with 13 optimisations — covering resource lifecycle management, DOM virtualisation, store bounding, and Three.js GPU memory efficiency.

---

## Ollama Cloud Provider

- New `ollama_cloud` provider calls `https://ollama.com/v1` directly (OpenAI-compatible), bypassing the local Ollama daemon.
- Multiple API keys supported (one per account) with sequential failover via `FailoverLLMProvider` + `CircuitBreaker`.
- `OllamaLLMProvider` gains `use_capacity_limiter` and `use_native_options` flags; cloud instances skip Redis capacity gating and the Ollama-native `num_ctx` injection.
- `OLLAMA_CLOUD_BASE_URL` and `OLLAMA_CLOUD_API_KEYS` (CSV) added to settings and forwarded to all containers in `docker-compose.yml`.
- Model registry entry for `ollama_cloud` defaults to `gemma3:27b`; additional entries: `gpt-oss:120b`, `kimi-k2-thinking`.
- Embeddings remain on local Ollama (Ollama Cloud `/v1/embeddings` returns 404).
- Cutover: set `DEFAULT_LLM_PROVIDER=ollama_cloud`, `DEFAULT_LLM_MODEL=gemma3:27b`, `OLLAMA_CLOUD_API_KEYS=<keys>`, restart. Rollback: revert two env vars, restart — no data migration required.
- `LoadBalancedLLMProvider` implemented for parallel Ollama Cloud usage across multiple keys.

## Hybrid Search

- BM25 sparse embedding support added for hybrid dense+sparse retrieval.
- `VectorSearcher` now combines dense and sparse results.
- Query timeout increased from 60 s to 120 s to accommodate the longer retrieval path.
- Nginx `location /api/health` added.

## MinIO Migration

- MinIO replaces Garage as the object storage backend for Milvus.
- `docker-compose.yml` now includes the MinIO service inline (previously only in the override file) so the base stack is self-contained.
- Milvus `MINIO_*` environment variables restored; `graphrag-minio-data` volume declared.
- `scripts/backup.sh` updated: `ALL_COMPONENTS`, `REQUIRED_CONTAINERS`, and the tar section now target the MinIO container / data volume instead of the retired Garage equivalents.
- `scripts/install_backup_cron.sh` added: installs a daily 02:00 backup cron with `--retention=7`.
- `scripts/cleanup_stale_uploads.sh` added: aborts stale MinIO multipart uploads.
- Documentation: `docs/PRs/MINIO_MIGRATION_RUNBOOK.md`, `docs/PRs/ROLLBACK_MINIO_MIGRATION.md`.
- Garage service commented out in `docker-compose.yml`; legacy volumes `amber2_graphrag-garage-data` / `amber2_graphrag-garage-meta` pending manual removal after stability confirmation.

## Frontend — Performance Optimisations (13)

A systematic performance audit of the React frontend produced 13 optimisations across three areas, delivered in three focused branches.

### Resource Lifecycle Management

| Component | Optimisation |
|-----------|-------------|
| `useChatStream` | Disabled per-chunk `console.log` active in production — eliminates string allocation and GC pressure on every streamed token |
| `CitationExplorer` | `setTimeout` id stored and cancelled on unmount / effect re-run — avoids state updates on unmounted components |
| `PDFViewer` | `pdfDocument.destroy()` called on file change — releases PDF.js worker memory and decoded page cache |
| `DocumentViewer` | Blob URL revoked on unmount via `useEffect` cleanup — frees `Blob` from renderer memory |
| `ChatContainer` | `stopStream()` called on unmount — aborts in-flight fetch reader and frees the response stream |
| `useInstallProgress` | `EventSource` closed on unmount — terminates the SSE connection and its associated socket |
| `LiveStatusBadge` | `status` removed from `useEffect` deps — eliminates unnecessary SSE reconnects on every status update |
| `DocumentLibrary` | Fuse.js keys array memoised — prevents full index rebuild on every render |

### Three.js GPU Memory Efficiency

- `disposeNodeObject()` helper added to `ThreeGraph.tsx`: traverses a `THREE.Group` and explicitly disposes geometry, materials, and — critically — calls `map.dispose()` on `SpriteMaterial` (Three.js 0.149 does not release `CanvasTexture` GPU memory via `material.dispose()` alone).
- `nodeObjectCache` ref (`Map<nodeId, THREE.Group>`) tracks all allocated objects. Before building a new object for a node, the stale cached object is disposed. On unmount, all entries are disposed and the map cleared. On `nodes` prop change, entries for removed nodes are pruned immediately.
- `GlobalGraphPage`: `interactionOrder` LRU ref bounds graph size. On each neighbourhood expand, the clicked node and new neighbours are promoted to the LRU tail. When `graphData` exceeds 400 nodes, the oldest entries are evicted and their edges dropped — prevents unbounded Three.js scene growth during long sessions.

### DOM Virtualisation and Store Bounding

- **Chat message store**: FIFO cap at 200 messages; `addMessage` trims oldest on overflow — bounds Zustand state and downstream re-render cost.
- **Citation store**: Map evicts the oldest entry when size exceeds 200 (insertion-order eviction via `Map.keys().next()`).
- **MessageList**: `useVirtualizer` with `measureElement` replaces full DOM rendering. Only visible messages are in the DOM. Scroll-to-bottom uses `scrollToIndex` with RAF debounce; `isStreaming` toggles `'auto'` vs `'smooth'` behaviour.
- **DocumentLibrary**: `AnimatePresence + motion.li` list (up to 10 000 DOM nodes at scale) replaced with `useVirtualizer`. Visible rows only; `measureElement` handles dynamic row heights. Container height `calc(100vh - 380px)`, minimum 400 px.
- **ContextSidebar**: `recentConversations` capped at 200 on infinite-scroll append.
- **ChatHistoryPanel**: `useQuery` + manual `offset` state replaced with `useInfiniteQuery` — single React Query cache key instead of one entry per pagination offset.

## Security

- **axios upgraded 1.13.x → 1.16.1** (non-breaking, within `^1.x` semver range). Fixes 16 CVEs including prototype-pollution gadgets in `parseReviver`, `mergeConfig`, `withXSRFToken`, and `validateStatus` — all reachable in the browser via crafted API responses.
- `lodash-es` bumped to 4.18.1 (prototype-pollution in `_.unset`/`_.omit`; ships in the production bundle via `react-force-graph`).
- `uuid`, `postcss`, `ajv`, `rollup`, `vite`, and 15+ transitive dependencies updated via `npm audit fix`.
- 5 remaining advisories (vitest/vite/esbuild dev-server chain) require `vitest@4.1.6` major bump — deferred; not exploitable in the deployed static SPA.
