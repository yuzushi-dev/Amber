## Release 1.1.0

**Branch:** `tenant-fixes-and-security-updates`  
**Period:** 2026-03-24 – 2026-03-26  
**Commits:** 20  
**Impact:** 75 files changed, 3,443 insertions, 327 deletions  
**Status:** Deployed to production via zero-downtime canary cutover

---

## Overview

This release is a comprehensive security hardening sprint addressing all findings from a
full production audit of the Amber2 GraphRAG platform. The audit covered 164 mounted API
routes, all repository and service layers, the worker surface, the operational control
plane, and the database access model.

The work is organised into 12 remediation tasks plus a 12-item gap analysis pass. Every
fix was delivered behind a canary deployment lane, validated by a dedicated security test
suite (103 tests), and then by an end-to-end integration test suite (81 tests spanning
the full user journey) before promotion to live.

No data was lost and no service downtime occurred.

## Security Hardening

### P0 — Agent Tool Escalation Contained (Task 2)

- **Feature flags added** (`enable_agent_mode`, `enable_maintainer_tools`,
  `enable_agent_graph_tool` in `config.py`), all defaulting to `false`. Agent mode,
  filesystem tools, and the graph query tool are now opt-in.
- **Privilege checks** added in both `query.py` (streaming) and `use_cases_query.py`
  before entering agent execution; callers without explicit feature-flag enablement
  receive HTTP 403.
- **Path traversal hardened**: `filesystem.py` `list_directory`, `read_file`, and
  `grep_search` now call `os.path.realpath()` and reject paths that resolve outside the
  allowed sandbox.
- **Graph tool** (`query_graph`) is disabled by default; when enabled it is still
  tenant-scoped.

### P0 — Control-Plane Lockdown (Task 3)

- **RAGAS evaluation router** guard elevated from `verify_admin` to `verify_super_admin`.
- **API key scope validation**: `admin/keys.py` now blocks non-super-admin callers from
  creating or patching keys that carry `super_admin` or `root` scopes, closing a
  privilege-escalation path.
- **`setup.py` import fix**: broken `from api.config import settings` (missing `src.`
  prefix) in `_check_db_migration_status` caused silent `None` returns.
- **Health endpoint sanitisation**: per-dependency error strings and the fallback
  exception detail no longer include DB hostnames, connection strings, or raw exception
  text.
- **Exception leakage sweep**: replaced `detail=str(e)` / `detail=f"…{str(e)}"` in HTTP
  500 responses across 14 route files (admin and non-admin).
- **Audit trail attribution**: `admin/config.py` `update_tenant_config` and
  `reset_tenant_config` now record `request.state.api_key_name`; `admin/curation.py`
  `resolve_flag` records the actual caller identity instead of the fixed string
  `"admin"`.

### P1 — Rules Scoped to Tenant (Task 4)

- `admin/rules.py` guard upgraded from `verify_admin` to `verify_tenant_admin`.
- `RulesService` — formerly a global singleton — now resolves rules per-tenant for each
  request.
- Three pre-existing `global_rules` rows with `tenant_id = NULL` were backfilled to
  `tenant_id = 'default'` via a data migration, removing the last globally-shared rules.
- Rules injection in generation and query pipelines now passes the authenticated
  tenant's rules only.

### P1 — Fail-Open Fallbacks Removed (Task 5)

- `query.py`, `documents.py`, `graph_editor.py`: `_get_tenant_id` /
  `get_current_user_tenant_id` helpers now raise HTTP 401 when
  `request.state.tenant_id` is absent, instead of silently falling back to
  `settings.tenant_id`.
- `query.py`, `chat.py`: new `_get_user_id()` helper raises HTTP 400 when the
  `X-User-ID` header is absent or blank; replaces `"default_user"` sentinel. Falls
  back to `api_key_name` so frontend flows (which do not send `X-User-ID`) are still
  attributed correctly.
- `use_cases_query.py`: `execute()` default `user_id="default_user"` changed to `""`.

### P1 — Graph Surface Role Enforcement (Task 6)

- `graph_editor.py`: `heal_node`, `merge_nodes`, `create_edge`, `delete_edge`,
  `delete_node` — all write handlers — now require `verify_tenant_admin`.
- `graph_history.py`: `apply_pending_edit`, `reject_pending_edit`,
  `undo_applied_edit`, and `create_pending_edit` all require `verify_tenant_admin`.
- `context_writer.py`: all five Cypher MATCH/MERGE queries (Conversation, Turn, Chunk,
  UserFeedback → Turn, Conversation → Turn link) now include `tenant_id: $tenant_id`
  in the node predicate and pass `tenant_id` in the parameter dict, preventing
  cross-tenant graph-node linkage via bare ID lookups.

### P2 — Secret Rotation Infrastructure (Task 7)

- **Dual-secret keyring** added to `shared/security.py`: HMAC verification tries
  `SECRET_KEY` first, then falls back to `SECRET_KEY_OLD` if set, enabling zero-downtime
  secret rotation. Tokens signed under the old key remain valid until the rollover
  window closes.
- `docker-compose.yml` passes `SECRET_KEY_OLD` and `DEV_API_KEY` through to containers
  so the rotation can be executed by updating `.env` and restarting without a code
  change.
- `IGNORE_EMBEDDING_MISMATCH=true` bypass removed from `docker-compose.yml`; startup
  embedding compatibility checks are now enforced unconditionally in production.
- **Operator action required**: the live `SECRET_KEY`, `DEV_API_KEY`, and Garage/MinIO
  credentials have not yet been rotated. Generate new values, update `.env`, and restart
  the API and worker containers to complete Task 7.

### P2 — SSE Ticket One-Time Use (Task 8)

- `auth.py` middleware: `redeem_ticket()` now uses Redis `GETDEL` instead of `GET +
  DEL` separately. Tickets are atomically consumed on first use, eliminating the replay
  window that previously existed within the TTL.
- Legacy `?api_key=` query-parameter SSE authentication fallback removed from the auth
  middleware; credentials-in-URL are no longer accepted.

### P2 — Operational Controls Fail-Closed (Task 9)

- **Rate limiter** (`rate_limit.py`): when Redis is unavailable, requests are rejected
  (HTTP 503) rather than passed through. Consistent fail-closed policy across all
  rate-limited endpoints.
- **LLM capacity limiter** (`llm_capacity.py`): `LLM_CAPACITY_FAIL_OPEN` env var added
  (default `false`); capacity checks now fail closed when Redis is absent.
- **Community task revocation** (`tasks.py`): when a tenant updates its config, only
  community-processing tasks tagged with that tenant's ID are revoked. Previously all
  queued community tasks across all tenants were cancelled.
- **Community refresh throttle** (`communities.py`): per-tenant 5-minute cooldown via
  Redis `SET NX EX`; returns HTTP 429 when cooldown is active, HTTP 503 if Redis is
  unavailable.

### P3 — Database-Layer Tenant Isolation (Task 10)

- **New Postgres role `graphrag_app`**: non-superuser, `NOBYPASSRLS`, `NOINHERIT`.
  Granted `SELECT / INSERT / UPDATE / DELETE` on all tenant tables and `USAGE /
  SELECT` on sequences. Default privileges set so future tables are covered
  automatically.
- **`FORCE ROW LEVEL SECURITY`** enabled on 8 tenant tables: `documents`, `chunks`,
  `feedbacks`, `folders`, `connector_states`, `conversation_summaries`,
  `graph_edit_history`, `api_key_tenants`.
- **New RLS policies** for the three tables that previously had none:
  `connector_states`, `conversation_summaries`, `graph_edit_history` — each scopes rows
  to `tenant_id = current_setting('app.tenant_id')`.
- `config.py`: `app_database_url` field (`APP_DATABASE_URL` env var) for the
  non-owner role connection. `main.py` uses it when set.
- `session.py`: `configure_worker_session()` sets `SET LOCAL app.is_super_admin = true`
  so Celery workers bypass RLS (they legitimately operate across all tenants).
- Workers (`backup_tasks.py`, `export_tasks.py`, `tasks.py`, `recovery.py`) all call
  `configure_worker_session()` at the start of each task.
- **Hostname fix** (`APP_DATABASE_URL` in `.env`): was `@localhost:5433` (host port),
  corrected to `@postgres:5432` (Docker network name). The previous value caused
  `Connection refused` inside containers, silently falling back to the superuser
  connection and bypassing all RLS enforcement.

### P3 — Connector Credential Encryption (Task 11)

- `shared/security.py`: `encrypt_credentials()` / `decrypt_credentials()` using Fernet
  symmetric encryption with a key derived from `SHA-256(SECRET_KEY)`.
- `connector_state.py`: `encrypted_credentials: Mapped[str | None]` column added
  (alembic migration `20260325_1500`).
- `connectors.py`: `authenticate()` writes the encrypted blob to
  `encrypted_credentials` instead of storing raw OAuth tokens, passwords, and
  subdomain strings in the `sync_cursor` JSONB column. All read paths (`browse`,
  background task, `sync`) decrypt from `encrypted_credentials`.

## Conversation History Fixes

Separate from the main task plan, a dedicated pass addressed conversation and user
identity consistency:

- `admin/chat_history.py`: added `verify_super_admin` router-level guard; previously
  any authenticated key could list, read, and delete conversations across all tenants.
- `query.py`: agent-mode `ConversationSummary` inserts now use `stream_user_id`
  (resolved from `X-User-ID` header or `api_key_name`) instead of the hardcoded
  `"user"` sentinel.
- `query.py`: sticky-mode auto-switch now verifies `tenant_id` against the existing
  conversation before trusting the conversation metadata; closes the cross-tenant mode
  injection vector.
- `query.py`: agent and RAG conversation-threading updates now verify `tenant_id` (and
  `user_id` for RAG) ownership before appending to an existing conversation thread.
- `connectors.py`: `is_authenticated` uses `encrypted_credentials` not `sync_cursor`
  after the Task 11 credential migration.
- `feedback.py`: removed `or "default"` tenant fallback; raises HTTP 401 when tenant
  is missing from request state.
- `setup.py`: router guard elevated from `verify_admin` to `verify_super_admin`.

## Bug Fixes Found by E2E Tests

Five security-relevant bugs were discovered and fixed during the e2e test run:

| Bug | File | Impact | Fix |
|-----|------|--------|-----|
| Cross-tenant document delete | `use_cases_documents.py` | Any tenant could delete another tenant's document (returned 204, silently removed the file and Milvus vectors) | Added `WHERE tenant_id = ?` filter for non-super-admin; raises 404 when document not found in caller's tenant |
| Unguarded community refresh | `communities.py` | Any authenticated user could trigger the expensive community detection pipeline | Added `Depends(verify_tenant_admin)` to `POST /v1/communities/refresh` |
| API key list cross-tenant leak | `api_key_service.py` + `keys.py` | `GET /v1/admin/keys` returned all active keys regardless of tenant context | `list_keys()` joins `ApiKeyTenant` and filters by `tenant_id` for non-super-admin callers |
| Super-admin document scoping | `documents.py` | Super-admin `list_documents` ignored `X-Tenant-ID` header; no way to scope the listing to a single tenant | Reads `request.state.tenant_id` (set from header by auth middleware) in addition to the `tenant_id` query param |
| Non-streaming chat history | `query.py` | `POST /v1/query` (non-streaming path) never wrote a `ConversationSummary`; chat history was empty after every non-streaming query | Added `memory_manager.save_conversation_summary()` call after response, mirroring the streaming path |

Additional stability fixes:

- `query.py`: called non-existent `update_conversation_summary` method introduced in the
  initial fix; corrected to `save_conversation_summary` with the correct signature.
- `communities.py`: `CommunityResponse` Pydantic model had non-optional `status: str`
  and `is_stale: bool` fields that could not accept `None` from Neo4j when community
  detection had not yet run; all five nullable fields made `Optional`.
- `config/settings.yaml`: `pool_size`/`max_overflow` increased from 5/5 to 15/15 to
  prevent DB connection pool exhaustion under concurrent test load.
- `llm_capacity.py`: `fail_open: bool = False` field was placed before required
  dataclass fields, causing a `TypeError` at import time on a cold container start;
  moved to the correct position.

## Breaking Changes

### For Operators

- **nginx now owns ports `:8000` and `:3000`**. Direct container port bindings for
  `api` and `frontend` were removed. Traffic enters exclusively through nginx.
- **`APP_DATABASE_URL` must use Docker network name** (`@postgres:5432`), not the host
  port (`@localhost:5433`). If cloning `.env` from another environment, update this
  value.

### For API Consumers

- `POST /v1/query`, `POST /v1/chat/history` endpoints, and `GET /v1/documents` now
  return HTTP **401** if `request.state.tenant_id` is not set (missing or expired API
  key). Previously they silently fell back to a default tenant.
- `POST /v1/query` and streaming query now return HTTP **400** if the `X-User-ID`
  header is absent or blank (unless a fallback to `api_key_name` applies).
- `GET /v1/communities/refresh` now requires **tenant_admin** role; previously any
  authenticated user could trigger it.
- Graph write endpoints (`heal_node`, `merge_nodes`, `create_edge`, `delete_edge`,
  `delete_node`, `create_pending_edit`, `apply_pending_edit`, `reject_pending_edit`,
  `undo_applied_edit`) now require **tenant_admin** role.
- SSE authentication via `?api_key=<key>` query parameter is no longer accepted.
  Use the `X-API-Key` header or the Redis-backed SSE ticket mechanism.
- SSE auth tickets are now **one-time-use** (consumed on first connection).
